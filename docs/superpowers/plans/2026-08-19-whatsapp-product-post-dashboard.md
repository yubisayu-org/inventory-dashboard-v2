# WhatsApp Product Posts — Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner compose a WhatsApp product post (upload or reuse a
photo, tag catalogue products with auto-issued codes, place pins, preview
the caption, send) and let the Order Requests inbox show and resolve
WhatsApp-sourced rows, including the `asking` disambiguation state — the UI
layer on top of the already-shipped backend (migration 081,
`lib/db/wa-sends.ts`, `lib/db/catalogue-requests.ts`'s WhatsApp extensions,
the worker resolution engine).

**Architecture:** Extends two existing screens rather than adding new ones:
`app/dashboard/catalogue-posts` gains a composer mode reusing its existing
upload form's shell; `app/dashboard/order-requests` gains a `source` badge
and an `asking`-row radio picker inside its existing per-row status
branching. New API routes wrap the existing `lib/db/wa-sends.ts` data layer
(no new backend logic — Tasks 1-10 of the backend plan already built and
reviewed everything this UI calls). A new product search-as-you-type route
is required — nothing like it exists yet, every current product picker in
this codebase filters client-side over a fully preloaded list, which the
spec explicitly rules out for 6,817 products.

**Tech Stack:** Next.js App Router (API routes + client components),
`postgres` (tagged templates, no ORM), Tailwind classes matching this
codebase's existing conventions (no component library, no toast library —
inline error banners and centered/bottom-sheet modals, per the established
patterns in `OrderRequestsClient.tsx`/`CataloguePostsClient.tsx`/`ShopPostClient.tsx`).

**Spec:** `docs/superpowers/specs/2026-08-19-whatsapp-product-post-design.md`
**Backend plan (prerequisite, already shipped):** `docs/superpowers/plans/2026-08-19-whatsapp-product-post-backend.md`

## Global Constraints

- Product search for the composer is server-side, `LIMIT 20`, matching name
  and store — never load the full catalogue client-side for this picker.
- The caption shown in the composer's live preview and the caption actually
  queued to `wa_outbox` must be generated by the SAME function
  (`renderCaption` from `lib/whatsapp/product-post.ts`, already built and
  tested in the backend plan) — never a second, parallel renderer.
- Pin placement is click-to-place (not drag), matching the codebase's one
  existing precedent (`app/dashboard/shop/[id]/ShopPostClient.tsx`) —
  normalized `0..1` coordinates via `getBoundingClientRect`.
- Every new API route under `app/api/whatsapp/sends/` is owner-only,
  matching the auth pattern already used by `app/api/sheets/catalogue-posts/route.ts`
  (`requireSession`/`requireOwner` from `lib/api.ts` — read that file's
  exact usage before writing a new route, copy its guard pattern verbatim).
- No new toast/notification library. No new modal library. Match the exact
  inline-error-banner and modal-shell conventions already in
  `OrderRequestsClient.tsx`/`CataloguePostsClient.tsx` (documented in each
  task below where relevant).
- `asking` is added to `getCatalogueRequests`'s `onlyPending` status filter
  (currently `('pending', 'offer_pending', 'approved')`) — an asking row
  needs owner attention just as much as a pending one. `rejected` rows
  (including WhatsApp closed-trip dead rows) are NOT added to that filter —
  they stay reachable only via the existing `?all=true` toggle, matching
  how a rejected catalogue-web row already behaves today. This is a
  deliberate design choice made while writing this plan (the spec doesn't
  specify inbox default-view visibility) — flag it in your task report if
  you disagree, but implement it as stated.

```ts
import { NextRequest, NextResponse } from "next/server"
import sql from "@/lib/db-pool"
import { requireSession, requireOwner } from "@/lib/api" // exact names/usage: confirm against lib/api.ts and catalogue-posts/route.ts first

export async function GET(req: NextRequest) {
  const session = await requireSession()
  if (!session) return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
  if (!requireOwner(session)) return NextResponse.json({ error: "Forbidden" }, { status: 403 })

  const q = req.nextUrl.searchParams.get("q")?.trim() ?? ""
  if (q.length < 2) return NextResponse.json({ products: [] })

  const rows = await sql`
    SELECT id, name, store, price
    FROM products
    WHERE active AND (name ILIKE ${"%" + q + "%"} OR store ILIKE ${"%" + q + "%"})
    ORDER BY name
    LIMIT 20
  `
  return NextResponse.json({
    products: rows.map((r) => ({ id: r.id, name: r.name, store: r.store, price: Number(r.price) })),
  }, { headers: { "Cache-Control": "no-store" } })
}
```

```ts
import { NextRequest, NextResponse } from "next/server"
```

```ts
import { renderCaption } from "@/lib/whatsapp/product-post"

export async function POST(req: NextRequest, { params }: { params: Promise<{ id: string }> }) {
  const session = await requireSession()

  if (!requireOwner(session)) return NextResponse.json({ error: "Forbidden" }, { status: 403 })

  const id = Number((await params).id)
  const send = await getSend(id)
  if (!send) return NextResponse.json({ error: "Not found" }, { status: 404 })

  }
  return NextResponse.json({ success: true })
```

- [ ] **Step 3: Implement**

```ts
export interface RepostCandidate {
  postId: number
  mediaUrl: string
  title: string
  taggedCount: number
  lastEvent: string
  lastSentAt: string
  orderCount: number
}

/**
 * Past posts worth sending again — only ones that have gone out at least
 * once (a pure draft, never sent, isn't "past" anything). One row per post,
 * summarizing its most recent send and, across every send, how many of its
 * requests converted to real orders — the signal that makes a post worth
 * repeating.
 */
export async function listRepostLibrary(limit = 30, db: DBExecutor = sql): Promise<RepostCandidate[]> {
  const rows = await db`
    SELECT
      cp.id AS post_id,
      cp.media_url,
      latest.title,
      (SELECT count(*) FROM wa_send_codes sc JOIN wa_sends s2 ON s2.id = sc.send_id WHERE s2.post_id = cp.id) AS tagged_count,
      latest.event AS last_event,
      latest.message_sent_at AS last_sent_at,
      (
        SELECT count(*) FROM catalogue_requests r
        JOIN wa_sends s3 ON s3.id = r.send_id
        WHERE s3.post_id = cp.id AND r.status = 'converted'
      ) AS order_count
    FROM catalogue_posts cp
    JOIN LATERAL (
      SELECT s.title, s.event, s.updated_at AS message_sent_at
      FROM wa_sends s
      WHERE s.post_id = cp.id AND s.message_id <> ''
      ORDER BY s.id DESC
      LIMIT 1
    ) latest ON true
    ORDER BY latest.message_sent_at DESC NULLS LAST
    LIMIT ${limit}
  `
  return rows.map((r) => ({
    postId: r.post_id as number,
    mediaUrl: r.media_url as string,
    title: r.title as string,
    taggedCount: Number(r.tagged_count),
    lastEvent: r.last_event as string,
    lastSentAt: (r.last_sent_at as Date).toISOString(),
    orderCount: Number(r.order_count),
  }))
}
```

Note `tagged_count` counts `wa_send_codes` rows across ALL of the post's
sends (not just the latest), matching "how many products this post has
ever carried a code for" — if you'd rather it reflect only the LATEST
send's product count, that's a defensible alternative reading; pick one and
be consistent with what the composer UI (Task 8) actually wants to display,
and note which you chose in your report.

```ts
// app/api/whatsapp/sends/[id]/caption/route.ts
import { NextRequest, NextResponse } from "next/server"
import { requireSession, requireOwner } from "@/lib/api"
import { getSend, listSendCodes } from "@/lib/db/wa-sends"
import { renderCaption } from "@/lib/whatsapp/product-post"

export async function GET(req: NextRequest, { params }: { params: Promise<{ id: string }> }) {
  const session = await requireSession()
  if (!session) return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
  if (!requireOwner(session)) return NextResponse.json({ error: "Forbidden" }, { status: 403 })

  const id = Number((await params).id)
  const send = await getSend(id)
  if (!send) return NextResponse.json({ error: "Not found" }, { status: 404 })
  const codes = await listSendCodes(id)
  return NextResponse.json({ caption: renderCaption({ title: send.title }, codes) })
}
```

```ts
// app/api/whatsapp/sends/[id]/products/[codeId]/pin/route.ts
import { NextRequest, NextResponse } from "next/server"
import { requireSession, requireOwner } from "@/lib/api"
import sql from "@/lib/db-pool"

export async function PUT(req: NextRequest, { params }: { params: Promise<{ id: string; codeId: string }> }) {
  const session = await requireSession()
  if (!session) return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
  if (!requireOwner(session)) return NextResponse.json({ error: "Forbidden" }, { status: 403 })

  const { codeId } = await params
  const { x, y } = await req.json()
  if (typeof x !== "number" || typeof y !== "number" || x < 0 || x > 1 || y < 0 || y > 1) {
    return NextResponse.json({ error: "x and y must be numbers between 0 and 1" }, { status: 400 })
  }
  await sql`UPDATE wa_send_codes SET point_x = ${x}, point_y = ${y} WHERE id = ${Number(codeId)}`
  return NextResponse.json({ success: true })
}
```
